# 最高标号预流推进

预留推进算法算法允许结点的流暂时不平衡，但最终推流完毕后，无法推入汇点的流会被推回源点。

将源点高度设置为 $|V|-1$，给源点设置一定的高度是为了避免中间点直接把流推回源点。这是由于中间点高度都不大于 $|V|-1$，这样流向原点的优先级很靠后。首先由源点向各个直连点推满流，并将这些点入队。
之后依次出队，假定当前出队点为 $u$，则检查所有的 $e_{u \rightarrow v}$，只要还有容量且高度差为 $h_u-h_v=1$，就向其尽量推流，推流大小取 $min(ex_u,cap_{u \rightarrow v})$。这里 $ex_u$ 指 $u$ 点的过剩流量，$cap_{u \rightarrow v}$ 指边 $e_{u \rightarrow v}$ 的剩余容量。
如果 $u$ 点所有可推的边都推完后，$u$ 流量还过剩，则需要扩大推流面。检查 $u$ 的所有没满流的出边（一定是有的，能来就能回，大不了就往回推），找到高度最小的一个点 $v$，将 $u$ 的高度重标为 $h_u=h_v+1$，然后再把 $u$ 再次入队，准备之后向下推。
在此过程中，源点和汇点都不需要重标高度和入队，即整个过程源点高度都是 $|V|-1$，汇点高度都是 $0$。
反复如此，直到队列为空，此时没能推入汇点的流量都被推回了源点。
这里有两个优化，如果一开始不设置初始高度，需要多次重标高度才能顺利把流推向汇点。因此可以首先从汇点做一次 $BFS$，给出一个初始高度便于推流。
优先取出高度高的点进行推流，这样一方面确保高点推流后低点才推流，避免低点先推流后重标记低点高度导致需要重标记高点高度，且便于合并多个流，提升推流效率。
在向汇点推流时，如果发现某结点有剩余流且该结点的高度 $h_u$ 在图中是唯一的，此时他重标记后，高度将出现断层，这意味着没有任何一个点能连向高度更小的点，即不可能流到汇点。此时可以直接把没在队列且距离大于 $h_u$ 的点的高度直接设置为 $|V|$，即 $h_{src}+1$，便于后续向起点推流。

```cpp
struct HLPP {
    int head[N], dis[N], gap[2 * N], n, tot;
    int to[M], nxt[M], src, dst;
    bool in[N];
    ll ex[N], cap[M];
    priority_queue<pii> pq;
    HLPP(int _n) : n(_n) { tot = 0, fill(head, head + n, -1), pq = {}; }
    void add(int u, int v, ll f, ll g = 0) {
        to[tot] = v, nxt[tot] = head[u], cap[tot] = f, head[u] = tot++;
        to[tot] = u, nxt[tot] = head[v], cap[tot] = g, head[v] = tot++;
    }
    bool bfs() {
        queue<int> q;
        fill(dis, dis + n, n), fill(gap, gap + n, 0), dis[dst] = 0, q.push(dst);
        while (!q.empty()) {
            int u = q.front(), v;
            q.pop(), ++gap[dis[u]];
            for (int i = head[u]; ~i; i = nxt[i])
                if (dis[v = to[i]] == n && cap[i ^ 1]) {
                    dis[v] = dis[u] + 1;
                    q.push(v);
                }
        }
        return dis[src] < n;
    }
    void push(int now) {
        for (int i = head[now]; ~i && ex[now]; i = nxt[i])
            if (cap[i] && dis[now] == dis[to[i]] + 1) {
                ll add = min(cap[i], ex[now]);
                cap[i] -= add, cap[i ^ 1] += add;
                ex[now] -= add, ex[to[i]] += add;
                if (!in[to[i]] && to[i] != src && to[i] != dst) pq.emplace(dis[to[i]], to[i]), in[to[i]] = true;
            }
    }
    void relabel(int now) {
        int ht = 2 * n;
        for (int i = head[now]; ~i && ex[now]; i = nxt[i])
            if (cap[i]) ht = min(ht, dis[to[i]]);
        if (dis[now] < n && --gap[dis[now]] == 0)
            for (int i = 0; i < n; i++)
                if (i != src && dis[i] > dis[now]) --gap[dis[i]], ++gap[dis[i] = n];
        ++gap[dis[now] = ht + 1];
        pq.emplace(dis[now], now), in[now] = true;
    }
    ll run(int _src, int _dst) {
        src = _src, dst = _dst;
        if (!bfs()) return 0;
        dis[src] = n - 1;
        for (int i = head[src]; ~i; i = nxt[i])
            if (cap[i]) {
                if (!in[to[i]] && to[i] != src && to[i] != dst) pq.emplace(dis[to[i]], to[i]), in[to[i]] = true;
                ex[to[i]] += cap[i], cap[i ^ 1] += cap[i], cap[i] = 0;
            }
        while (!pq.empty()) {
            auto [_, now] = pq.top();
            in[now] = false, pq.pop();
            push(now);
            if (ex[now] && now != src && now != dst) relabel(now);
        }
        return ex[dst];
    }
    void clear() {
        fill(head, head + n, -1);
        tot = 0;
    }
};
```

复杂度来源于几个：对点提升高度，对边进行访问。
对点提升高度：
如果一个结点一轮推流完成后，仍有超额流，结点高度会提升。由于每个结点最多提升 $O(V)$ 次，一共 $V$ 个结点，所以一共提升 $O(V^2)$次。
对边进行访问：
为了确定提升的高度，对每个点，需要遍历所有出边对应的点，考虑 $O(V)$ 的高度范围，合计考虑的出边是 $O(VE)$ 量级。
每个点提升高度后，需要遍历所有边进行推流，如果能推满，那么这条边只访问一次，在最坏情况下，所有高度都需要把所有出边跑一边，总复杂度 $O(VE)$。
如果一条边不能推满，那么可能会多次访问，可以运用势能分析，记 $\Phi=\sum h_i$。对于出现一条边推不满的情况，由于 $h_u=h_v+1$，会使势能函数减 $1$ 或者 $h_u$。势能函数只有在有点入队的时候才会增加，而每个点每次入队都会变大，故最多为势能函数贡献大约 $1+2+...+2|V|-1=V^2$，故所有点贡献为 $O(V^3)$。
因此总复杂度为 $O(V^2+VE+V^3)=O(V^3)$。

采用优先队列后，可以证明复杂度降到 $O(V^2\sqrt{E})$。
