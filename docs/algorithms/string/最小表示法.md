---
title: "最小表示法"
catagory: string
---

一个字符串，如果循环等价，则存在一个最小的字典序表示。

字符串长度为 $n$，先复制一倍拼接在后面。
设置两个游标 $x=1,y=2$，不断比较以这两个游标开始的串大小。

$k$ 从 $0$ 开始，比较 $s_{x+k}$ 与 $s_{y+k}$ 的大小，会产生三种结果：
$s_{x+k}=s_{y+k}$，则 $++k$，继续比下一个位置。
$s_{x+k}<s_{y+k}$，则 $y+=k+1$，并重新比较。
$s_{x+k}>s_{y+k}$，则 $x+=k+1$，并重新比较。
第一种情况很自然。关键是另外两种情况为何可以直接跳过中间k个位置。
不失一般性，假定出现了 $s_{x+k}>s_{y+k}$，那么说明 $s_{x...x+k-1}=s_{y...y+k-1}$，
那么从 $x$ 到 $x+k$ 的某位置 $x+i$ 作为起点的字符串 $s_{x+i...x+k}$，会输给从 $y+i$ 作为起点的串 $s_{y+i...y+k}$。
这就意味着从 $x\sim x+k$ 都不可能作为起点，所以x的起点可以直接跳过这一段。

有两种情况结束比较：
$k$ 增长到字符串长度 $n$ ，这说明从 $i$ 开始和从 $j$ 开始得到了一样的串，就是结果。
$xy$ 其中一个游标的起点超出了字符串，则另一个游标即为答案的起点。
注意：如果中途出现 $x=y$ 的情况，随意错开一位即可。

```cpp
int getST(char s[], int n) {
    int i = 1, j = 2, k;
    while (i <= n && j <= n) {
        k = 0;
        while (k < n && s[i + k] == s[j + k]) k++;
        if (k == n) break;
        if (s[i + k] > s[j + k])
            i += k + 1;
        else
            j += k + 1;
        if (i == j) j++;
    }
    i = min(i, j);
    s[i + n] = 0;
    return i;
}
```
